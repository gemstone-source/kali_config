# Troubleshooting

## Nothing happens when I log in (black screen)

- Make sure you selected the **Hyprland** session, not your desktop's default.
- Install/check your GPU driver for Wayland support.
- Look at logs: `journalctl -b0 -t hyprland` or `~/.local/share/hyprland/hyprland.log`.

## Hyprland says `hyprland-guiutils` is missing

Install the runtime dependency once:

```bash
sudo apt install -y hyprland-guiutils
```

It is included in `packages.list`, so future runs of `setup.sh` install it
automatically.

## The top bar (Quickshell) doesn't appear

- Quickshell config lives at `~/.config/quickshell/shell.qml`. Run it manually to
  see errors: `quickshell` (from a terminal inside Hyprland).
- Make sure `rice theme set <theme>` has been run at least once (it generates
  `~/.config/quickshell/Colors.qml`).
- Fall back to Waybar: run `waybar &` and disable Quickshell by removing its
  `hl.exec_cmd(...)` line in `~/.config/hypr/autostart.lua`.

## Quickshell crashes / "invalid arguments for wl_surface.attach"

This happens on VMs and machines without proper GPU/3D acceleration (e.g.
VMware SVGA II). Quickshell's hardware rendering path fails to negotiate a
buffer with the compositor.

**Fix:** run it with software rendering:

```
exec-once = env QT_QUICK_BACKEND=software quickshell
```

This is already set in `~/.config/hypr/autostart.lua`. If you're on real
hardware with working GPU drivers, you can remove the `env QT_QUICK_BACKEND=software`
part for faster rendering.

## VMware shows two mouse pointers

The VMware guest can expose USB and PS/2 mouse devices at the same time. The
rice forces Hyprland's software cursor path for pointer reliability. If two
pointers remain after a Hyprland restart, remove the duplicate PS/2 mouse
device from the VM hardware settings and keep the VMware virtual USB mouse
enabled.

## Bar shows no CPU/RAM/IP

The `Stats` widget reads from `~/.local/bin/rice-stats`. Make sure it exists and
is executable:

```bash
ls -l ~/.local/bin/rice-stats
~/.local/bin/rice-stats   # should print "CPU ..% · RAM ..% · eth0 <ip>"
```

The IP shows `eth0` when no `tun0` (VPN) is connected; otherwise it shows `tun0`.
Edit `bin/rice-stats` in the repo to change interface names.

## Colors didn't change after switching theme

Run `rice theme set <theme>` again, then `hyprctl reload`. Borders come from
`~/.config/hypr/theme.lua`; the anime wallpaper rotation is provided by
Quickshell, so restart it if needed:
`pkill -x quickshell; quickshell`.

## Launcher shows wrong/old colors

The wofi style is at `~/.config/wofi/style.css`, regenerated by `rice theme set`.
If it looks stale, re-run `rice theme set $(rice theme current)`.

## Font looks wrong / missing glyphs

`setup.sh` installs JetBrainsMono Nerd Font into `~/.local/share/fonts`.
Run `fc-cache -f` and log out/in if glyphs are still missing.

## Backups

When `setup.sh` finds an existing config it doesn't own, it moves it to
`<name>.bak.<timestamp>` rather than overwriting it. Look there if you lost a
setting.

## Fully reset

See the uninstall steps in `docs/install.md`.
